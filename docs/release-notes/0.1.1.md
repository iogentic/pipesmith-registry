# Pipesmith Registry 0.1.1

## Fixed

- Container image: `/data` belongs to the image user 65532, and `PIPESMITH_REGISTRY_DATA=/data` is set. An empty Docker volume on `/data` works. With 0.1.0, `store add` failed there with `Permission denied`.

## Added

- `scan` and `serve` warn when the data directory lies on a Docker Desktop share, FUSE, NFS or SMB.
- Reason: on such a file system two processes on one index lose writes. A scan and a server that started and stopped during it left the index without the tables of the scan. Measured on a Docker Desktop bind mount in 4 of 4 runs, on ext4 in 0 of 2.
- README and manual: section Container, with a Docker volume for `/data`.

## Changed

- The refusal of a bind address that is not local names the way to it: imported users and `--server-names`, or `serve --bind` instead of `bind` in `config.json`.
