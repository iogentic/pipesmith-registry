# Pipesmith Registry 0.1.3

## Fixed

- With `state.sqlite` in place, every answer with a stored file carries `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox`. A stored HTML or SVG file runs no script and sends no form. 0.1.2 sent the stored type alone, so a stored page could act with the session of a user who opened it.
- Overview draws each card as soon as its own request answers. 0.1.2 showed Loading until the slowest request had answered, which after a start on a large index could take seconds.
- `SHA256SUMS` lists each release file once. The file of 0.1.2 lists three names twice.

## Added

- Writes: clients deploy, publish, push and upload to hosted repositories of Maven, npm, Docker and raw. The server takes `mvn deploy`, raw `PUT` and `DELETE` by path, `npm publish` with dist-tags, `docker push` with blob uploads, and the REST component upload with asset and component delete. Writes are off by default. `serve --writes` turns them on. Without the option, the variable `PIPESMITH_REGISTRY_WRITES` decides: `1`, `true`, `on` or `yes` turn writes on, and `0`, `false`, `off` or `no` turn them off, whatever `config.json` says. Without the variable, `"writes": true` in `config.json` turns them on.
- Writes: every write goes into one store of this server, `stores/local-write` in the data directory. The store has the layout of a file blob store. `serve` creates it at the first start with writes on. The server never writes to a store of the old product. A delete sets a delete mark and removes no file.
- Writes: `serve --writes` needs `state.sqlite`. A write needs the right on the repository for its action: `add` for a new path, `edit` for a change and `delete` for a delete. A write without credentials answers `401`, also with anonymous access on. A write that a browser page of another origin sends answers `403`.
- Writes: each hosted repository keeps its write policy (`ALLOW`, `ALLOW_ONCE`, `DENY`), its Maven version and layout policy and its content type check from the import. A body may have up to 10 GiB, and a larger one answers `413`. A write leaves 2 GiB of free space on the disk, and one that would go below answers `507`. The record of the repository holds both limits as `max_body_bytes` and `free_space_floor_bytes`.
- Writes: `GET /service/rest/v1/status/writable` answers `200` while the write store takes writes. It answers `503` with writes off, as in 0.1.2.
- Writes: `maven rebuild-metadata <repository>` writes `maven-metadata.xml` and its checksum files again from the files the repository holds. `--group`, `--artifact` and `--version` narrow it. It refuses to run beside a `serve` with writes on.
- Security: `serve --tls-cert FILE --tls-key FILE`, or `tls_cert` and `tls_key` in `config.json`, turn on TLS for the main port and every Docker port. The listeners take TLS 1.2 or newer and HTTP/1.1.
- Security: `trusted_proxies` in `config.json` lists the reverse proxies whose `X-Forwarded-For` and `X-Forwarded-Proto` count. The list is empty by default, and no option sets it. A request with forwarded headers from another peer writes a warning, at most once per peer in 10 minutes.
- Security: `npm login` gets an npm token while the realm `NpmToken` is active. `docker login` gets a bearer token from the token route of a Docker repository while the realm `DockerToken` is active and the repository does not force Basic. A Docker token lives 300 seconds in memory. `token issue <user> --kind {npm,user}` prints a token once, and `token list` and `token revoke <id>` manage them. A user token also works as the Basic password of its user while `User-Token-Realm` is active. A user holds at most 20 tokens of each kind, and a new one revokes the oldest.
- Security: identity commands act on `state.sqlite` with the rights of the data directory owner and need no sign in: `user add|password|enable|disable|roles`, `anonymous on|off`, `realms list|set`, `ldap password|ca|check` and `token issue|list|revoke`. A running `serve` takes a change within about a second. `realms set` replaces the list of active realms and their order. An imported realm order lacks the token realms, so name them there.
- Security: the sign in limits count failures per pair of user name and client address. After 5 failures the pair waits 2 seconds, and each further failure doubles the wait, up to 15 minutes. A waiting pair gets `429` with `Retry-After`, also for the right password. A successful Basic check is kept for 300 seconds. At most 16 checks run against one LDAP connection at a time, and at most 64 more wait for a place.
- Security: `ldap password <connection>` writes a bind password into `secrets/` of the data directory, mode 0600. `serve` reads that file after `PIPESMITH_REGISTRY_LDAP_PASSWORD_<ID>` and before the prompt of `--ask-ldap-password`. `ldap ca <connection> <file|none>` names CA certificates for an `ldaps` connection.
- Security: `routes --json` prints the route table of the binary as JSON. The command is not in the help.
- Updates: `update <release directory>` checks a signed release with the trusted key of `update.json` and installs it below `releases/` of the install root. It then switches the link `current`, restarts the systemd unit and waits for its health. When the health check fails, it goes back by itself and restores the copies of migrated data files. `update --fetch` downloads and checks a release from a Forgejo package registry. `update --switch <version>` installs a fetched release. `rollback` switches back to the release before. `schema` prints the schema numbers of the data files that the binary knows.
- Updates: the install root is `/opt/pipesmith-registry` unless `--root` names another. `update.json` there needs `trusted_key` and `data_dir`. The unit is `pipesmith-registry.service` unless `unit` names another. The source repository holds a daily timer for `update --fetch --scheduled`, which switches only when `scheduled_switch` is true.
- Browse: a viewer shows text files of a repository in the browser, with search, go to line, folding and copy. It reads at most the first 2 MiB and 1,000,000 lines of a file. The button Open in viewer is in the head of a repository and of a folder, and View is in the detail of a file.
- Browse: Export sends the files of a folder, or one Docker image, as one archive. The form follows the format: `maven`, `npm` and `zip` give a zip, and `oci` gives a tar in OCI image layout for `docker load -i <name>`. The route is `GET /api/export/<repository>`, and `dry=1` answers the counts without the archive.
- Documentation: the manual is part of the binary at `/manual/`. The interface links to it as Documentation and to its API page as API, below the sign in form and in the user menu. `GET /api/openapi.json` answers an OpenAPI 3.1.0 document of the routes. Both need no sign in. The release holds the manual as a PDF, and an About dialog shows the version and the licence.

## Changed

- The first command of 0.1.3 that opens `state.sqlite` migrates it from schema 1 to schema 2. `serve`, `state show` and `user add` are such commands. `repos`, `store list` and `config --check` do not open the file. The command writes the copy `state.sqlite.v1` before (see Upgrade).
- Every `scan` also writes `catalog.sqlite` beside `index.sqlite`. Nothing reads it yet.
- `serve` waits `PIPESMITH_REGISTRY_DRAIN` seconds, 1 to 3600, for open requests at a stop. Unset, it waits 5 seconds, as before.
- `GET /api/status` gives the data directory, the bind address and the roots of the stores only to a user with the permission `nexus:blobstores:read`. Other signed in users get these fields as null.
- A search value that is no UTF-8 text or holds a NUL byte answers `400`.
- Remote addresses appear without user and password in REST answers, in `repos --json` and in `state show`.
- A Maven metadata document of a group member may expand to 8 MiB and nest 1,102 elements deep. An npm tarball may inflate to 1 GiB. A document or tarball over a bound is left out.
- A `.zst` manifest runs `zstd` from an absolute entry of `PATH` only, with a small set of variables.
- A network bind needs someone in `state.sqlite` who can sign in: an active local user with a password, or an LDAP connection, each with its realm active. 0.1.2 needed only the file `state.sqlite`. A network bind without TLS writes a warning at every start.
- The interface uses the full width of the window. 0.1.2 stopped at 1180 pixels.

## Upgrade

- Verify the download, stop the service, replace the binary and start it again. In a container, run the image `0.1.3` on the same `/data` volume.
- 0.1.3 uses `config.json`, `repositories.json` and `index.sqlite` of 0.1.2 as they are.
- The first command of the new binary that opens `state.sqlite` writes the copy `state.sqlite.v1` with mode 0600, then migrates `state.sqlite` to schema 2. The copy holds the rows of the file before the migration, and it stays. It holds the password forms of 0.1.2, also the unsalted SHA-1 and MD5 forms that later sign ins replace in `state.sqlite`. Delete it when you no longer need the way back.
- When `state.sqlite.v1` already exists at a migration, the command stops and asks you to move the copy away. Do not run a command of 0.1.3 on the data directory of a running 0.1.2 server.
- Without the write setting the server takes no write and answers deploys, publishes and pushes as 0.1.2 does.
- An install that binds a network address needs a user who can sign in (see Changed). Check with `realms list` and `user add` before the start.
- The first `scan` after the upgrade writes `catalog.sqlite` with mode 0600. Until then the server answers as before.
- An install moves into the layout of `update` by hand: the manual shows the four steps. 0.1.2 has no `update` command, so 0.1.3 is the first release in that layout.
- The way back to 0.1.2 has four steps. `serve` and `state show` of 0.1.2 stop on a `state.sqlite` of schema 2 with the message `has schema 2, this binary knows schema 1`.
  1. Stop the server of 0.1.3.
  2. Move `state.sqlite`, `state.sqlite-wal` and `state.sqlite-shm` out of the data directory.
  3. Rename `state.sqlite.v1` to `state.sqlite`.
  4. Put the 0.1.2 binary back and start it.
- 0.1.2 ignores the keys `writes`, `tls_cert`, `tls_key` and `trusted_proxies` in `config.json` without a warning. With `tls_cert` set it listens in plain HTTP. Put a TLS proxy in front of it or change the addresses of the clients before you go back.
- 0.1.2 leaves `catalog.sqlite` and `stores/local-write` as they are. A path written with 0.1.3 answers `503` in 0.1.2, and `repos` still counts it, because `index.sqlite` holds its row. To clear these rows, move `index.sqlite` away and run `scan` with 0.1.2. The path then answers `404`.
- Users, roles, realms and tokens changed after the upgrade are lost on the way back.
- After a way back, `serve` of 0.1.3 migrates the file again and writes a new `state.sqlite.v1`. It serves the files in `stores/local-write` again.
- We ran the way back once with both binaries on the development machine, on a data directory with one store of four files, on 2026-11-19.

## Limits

- Writes: with writes on, the interface still shows the server as read only and blocks its own write actions. Clients can write. `GET /service/rest/v1/read-only` still answers `"frozen": true`.
- Writes: on the development machine, 8 connections wrote 10,000 files of 4 KiB at about 60 `PUT` per second, measured on 2026-11-19. An earlier build of this version wrote about 110 per second, and the cause of the drop is not known yet. The rate of large bodies did not change.
- Writes: replaced and deleted files stay on disk with a delete mark, so the write store only grows. Each deploy writes `maven-metadata.xml` again, and each publish writes the package document again.
- Writes: some faults are repaired only by the next `scan`. A power loss can drop index rows of acknowledged writes or bring back the row of an acknowledged delete. A kill at the wrong moment can leave a file without its properties file, which nothing removes. A write that creates a folder in the first milliseconds of a scan can lose its row until the next scan. A delete during a scan of the write store can answer `404` although it set the mark.
- Writes: a scan holds the index for its whole walk. A write waits up to 10 seconds for it and then answers `503` with `Retry-After: 10`.
- Writes: an upload of several files is not atomic. A REST upload of several files, an npm publish and a delete of several paths stop where they fail and keep what they wrote before.
- Writes: a body without a declared length is bound by the free space above the floor, measured once. Parallel bodies each see the same free space.
- Writes: there is no bound on parallel writes. An npm publish holds up to 16 MiB of JSON in memory. Each `.md5`, `.sha256` and `.sha512` `PUT` hashes its whole artifact again. A body has 30 seconds per chunk and no total time limit.
- Writes: a path that a store of the old product holds can be written again but never deleted (`409`). No command changes the write policy or the limits of a repository.
- Writes: a checksum file that does not match its file is stored with a warning in the log. A client that verifies checksums fails at the download.
- Writes: `maven rebuild-metadata` of a whole repository drops metadata that no stored artifact supports. It takes no lock against a deploy of the same artifact.
- Writes: Docker upload sessions live in memory, 256 per process and 64 per user. A restart ends pushes in progress, and a session ends after one hour without a request.
- Writes: Docker referrers and the OCI subject field are not built, and a schema 1 manifest is refused. A request for a manifest by a reference that is neither a tag nor a digest answers `400` with `MANIFEST_INVALID`, where the OCI conformance tests expect `404`. For these two reasons 8 of the 80 conformance tests are left out.
- Writes: Gradle publish, raw writes with curl and a push of an image index with crane are not in the client tests.
- Writes: with writes off, `DELETE /service/rest/v1/components/{id}` answers `404`, also without credentials. With `state.sqlite` in place, the other refused REST writes answer `401` without credentials.
- Writes: a restart forgets the times of deleted files. A clock that steps back after a restart can sort a new write behind a delete of the same path.
- Writes: `catalog.sqlite` has no reader yet and no switch. Every scan writes it, at about 450 bytes and about 9 microseconds more per file and about 0.7 GB more peak memory. These figures come from a generated manifest on the development machine on 2026-11-18. It follows writes and deletes only at the next scan.
- Security: with anonymous access on, `GET /v2/` of a Docker port answers `200` without credentials, also where the repository forces Basic. `docker login` then checks no password.
- Security: behind a reverse proxy that is not in `trusted_proxies`, every client has the address of the proxy. Five wrong passwords for one name then block that name for everybody for up to 15 minutes, and the session cookie gets no `Secure`.
- Security: the table of the sign in limits holds 10,000 pairs. When all of them are blocked or have a check running, every new pair gets `429` until one of them expires, also with a kept successful check.
- Security: a kept successful check forgets no failure. One job with an old password behind the same address keeps the name at `429` for every job there, up to 15 minutes at a time.
- Security: a sign in of the interface and `npm login` get `429` at once while 5 checks of their pair run. Only Basic requests wait for a place.
- Security: a flood of unknown names takes the 16 places of an LDAP connection before every sign in that needs the directory. A directory that does not answer counts a failure for the right password.
- Security: the limits have no bound per address alone. An IPv6 client that changes its address inside its /64 counts as a new pair each time. Sharp s and ss, and final sigma, count as different names.
- Security: a token of a directory user works while the directory finds the entry, a locked account included. It follows the name to a new entry of the same name.
- Security: while any directory does not answer, npm and user tokens of directory users are refused at once. A refusal that a directory answered, for a name that no directory or more than one directory holds, is kept for 300 seconds.
- Security: a name that two directories hold is refused for tokens. With two connections to replicas of one directory, every npm and user token of every directory user is refused.
- Security: a removed directory user or a lost group still works for up to 300 seconds with Basic and tokens. A session keeps its groups until it ends, up to 12 hours.
- Security: npm and user tokens do not expire. A revoke or a new password does not end live sessions (up to 12 hours) or Docker tokens (up to 300 seconds). An npm token from `npm login` stays valid after a new password.
- Security: a Docker token works on every route its user may use and is bound to no repository. Docker tokens cannot be listed or revoked. Tokens of the old product are not taken over.
- Security: a Docker token of a removed local user signs in a user of the same name that is added within the 300 seconds of the token. The warning for forwarded headers keeps at most 100 peers, so a flood of peers can hide a new one. The Bearer realm and the addresses in npm and REST answers copy the port and the case of the Host header.
- Security: `anonymous on --user <id>` without `--roles` gives every request without credentials the rights of that user.
- Security: stored HTML, such as Javadoc in a raw repository, runs no script and sends no form while `state.sqlite` is in place. It still opens on the host of the registry, with its links.
- Security: one certificate serves every listener. A renewed certificate takes effect at the next start, and the mode of the key file is not checked. On a TLS listener the scheme is always https. `FORWARDED_ALLOW_IPS` trusts loopback by default.
- Security: the CA file of `ldap ca` is read through symbolic links, without a check of owner or mode. The warning for plain `ldap` covers the service bind only. Role names from `memberOf` are not checked against the group base.
- Security: the bind rule does not count anonymous access. A server for anonymous access alone needs a user or an LDAP connection before it binds a network address.
- Security: the import does not bring the default role of the old product, and its authorizing realm has no effect. `realms set <realms> --default-role <role>` sets a default role.
- Security: while `state.sqlite` cannot be read, the last loaded state stays, so a user disabled meanwhile still signs in.
- Security: `state.sqlite.v1` keeps the unsalted SHA-1 and MD5 password forms, and every command migrates, a read included.
- Security: sessions live in memory, and a restart signs everybody out. A new password keeps the live sessions of its user.
- Security: a stop with Ctrl Z during the password prompt leaves the terminal without echo.
- Security: the TLS listener, a TLS proxy in front of the server and the systemd unit have not run on a Linux host. Memory and CPU on a host are not measured.
- Security: this release has no tests that send hostile program arguments (command injection) or hostile archive entry names (zip slip) to the server. A review read the code for both. The server starts one program, `zstd` for a `.zst` manifest. The import never uses the name of an archive entry as a file name. These tests, a fuzz run of the two parsers and a check of the server patterns against slow input are planned for 0.1.4.
- Updates: `update` and `rollback` need systemd and do not apply to a container. No command makes the install root or installs the unit files.
- Updates: `update` has run in an Ubuntu 24.04 container with systemd. The fetch stage has run against a local stub only, and no update has run on a host.
- Updates: `update` trusts the key that `trusted_key` names. The project does not yet publish that key in a second place.
- Updates: the `SHA256SUMS` of 0.1.2 lists three names twice. `update` refuses a name listed twice, so it cannot install 0.1.2. The way back to 0.1.2 is by hand (see Upgrade).
- Updates: `rollback` restores no data file and checks no signature. It refuses when a data file has a newer schema than the release before writes. `update` writes no history.
- Updates: the health wait does not see `serve --port`. A unit that listens on another port than `config.json` or `PIPESMITH_REGISTRY_PORT` names needs `health_address` in `update.json`.
- Updates: the fetch stage reads one package of one owner on one Forgejo server and follows no redirect to another host.
- Updates: copies `<file>.v<n>` and `<file>.failed` stay in the data directory until you move them away. `update` refuses to run while one exists.
- Browse: the viewer only reads. It shows at most 2 MiB and 1,000,000 lines of a file. The button Wrap works in files of up to 5,000 lines. At 390 pixels its toolbar takes five rows.
- Browse: in the viewer a click on a folder of the file tree closes the open file. Some token colours fall below a contrast of 4.5 to 1 on the background of a match.
- Browse: an export holds at most 20,000 files and 2 GiB, counted from the index, and no setting changes that. The server streams two exports at a time and one per account. An export ends after 2 hours, or after 60 seconds in which the browser reads nothing, and has no resume.
- Browse: a Docker repository exports one image per archive and no folder. `docker load` names an exported image with the registry `docker.io`. A name of one part becomes `docker.io/library/<image>`, and a name with a slash becomes `docker.io/<name>`. A name that begins with a host stays as it is.
- Browse: a Maven export unpacked into `~/.m2/repository` serves releases only. As a `file://` repository it serves releases and SNAPSHOT versions.
- Browse: names that Windows reads in another way, such as `C:evil.dll` or a name with a trailing dot, pass into the archive. This has not been checked on Windows.
- Documentation: the OpenAPI document has schemas for error answers and for the bodies of write requests. It describes the other answer bodies in words.
