# Pipesmith Registry 0.2.0

0.2.0 adds proxy and group repositories that fetch from their remotes. The interface and the REST API change users, repositories and tasks. The server writes log files with audit lines, sends them to log targets and keeps figures of traffic and load. The release is signed with cosign. `state.sqlite` moves to schema 5 and `catalog.sqlite` to version 4 (see Upgrade). Writes and requests to remotes stay off until you turn them on.

## Fixed

- With writes on, the interface shows the server as writable and offers its write actions. 0.1.3 showed it as read only.
- A Docker port asks for credentials at `GET /v2/` where the repository forces Basic, also with anonymous access on. 0.1.3 answered `200` there, so `docker login` checked no password.
- Docker referrers and the OCI `subject` field are built, and the Bearer challenge carries the scope. Of the 80 OCI conformance tests, 72 passed, 5 were skipped and 3 are left out in the client run of 2026-11-20. 0.1.3 left out 8.
- A start with writes on keeps the order of writes and deletes of a path, also when the clock steps back after a restart. A delete mark that waits survives a restart.
- Two bodies without a declared length that arrive together stop at the free space floor. In 0.1.3 each saw the same free space.
- A `DELETE` during a scan of the write store answers `204`.
- A failed REST upload of several files takes back the files it wrote.
- An LDAP group member attribute may carry a matching rule, such as `member:1.2.840.113556.1.4.1941:` for nested groups of Active Directory.
- A directory that does not answer no longer counts a failure for the right password.
- A Docker token of a removed local user no longer signs in a new user of the same name.
- The warning for forwarded headers of an untrusted peer also names a new peer after its table of 100 peers is full.
- A stop with Ctrl Z during a password prompt leaves the terminal with echo on.
- In the viewer a click on a folder keeps the open file. Every token colour has a contrast of at least 4.5 to 1 on the background of a match (lowest pair 4.64 to 1). At 600 pixels and below the toolbar takes two rows.
- The viewer reads files with CRLF line ends, tabs and no final line break, and folds comments of XML and YAML.
- An export refuses entry names that Windows reads in another way: a colon, a trailing dot or space, and direction characters.
- The dry call of an export counts merged `maven-metadata.xml` files.
- A scan logs and skips a properties file with a number that does not fit, and goes on.

## Added

- Proxies: proxy repositories answer from their cache and, with upstream on, fetch from their remote what the cache lacks or holds too long. `serve --upstream` turns this on. Without the option, the variable `PIPESMITH_REGISTRY_UPSTREAM` decides, then `"upstream": true` in `config.json`. Upstream is off by default, and then no request leaves the server.
- Proxies: a fetched file is stored in full and checked before the client gets its first byte. The checks: a Maven file against the `.sha1` of the remote, an npm tarball against `dist.integrity` or `dist.shasum`, a Docker manifest or blob against its digest. Fetched files go into `stores/local-write`, also with writes off.
- Proxies: the ages, the 404 memory, the timeout of 20 seconds and the 2 retries come from the imported attributes of each proxy, with 1440 minutes as the default age. After three failures in a row a remote is blocked for 60 seconds, and each failed probe doubles the wait up to one hour. A blocked or failing remote leaves the cached copy in service.
- Proxies: `repos remote-secret <repository>` reads the password or token of a remote from standard input and writes `secrets/remote/<repository>` with mode 0600. The import keeps the user name and drops the password.
- Proxies: routing rules of the import allow or block paths of a proxy. Groups ask their members in order, and merge `maven-metadata.xml`, npm package documents and Docker tag lists over their members. `POST /service/rest/v1/repositories/<name>/invalidate-cache` and the button Invalidate cache make every cached copy stale.
- Proxies: the server writes one log line per request to a remote, with host, port and status or kind of failure, and no path.
- Proxies: on the development machine, the first byte of a 1 GiB layer took 4,243 ms uncached and 14 ms cached (`docs/measurements/phase-5.md`).
- Administration: the screens of the interface and their REST routes change users, roles, anonymous access, active realms and LDAP connections. An LDAP connection can be created, saved, ordered, deleted and checked, and its cache cleared. Its bind password lives only in a file of `secrets/` with mode 0600.
- Administration: blob stores and repositories can be created, saved and deleted, and `rebuild-index` runs for a repository. Twelve kinds of repository can be created, and other kinds answer `501`.
- Administration: routing rules can be created, saved, deleted, tested and previewed. A saved rule applies from the next request. Capabilities can be listed, saved and deleted, and system information can be read.
- Administration: tasks can be listed, read, run and stopped, and `serve` runs a scheduler for them. An administrator can put the server in read only mode. A freeze waits up to 30 seconds for running writes. Until it is released, it refuses writes and skips scheduled runs.
- Administration: a change through the interface or REST cannot grant rights the signed in user does not hold. Such a request answers `403` with `grant-exceeds`.
- Administration: the import also brings cleanup policies, tasks and capabilities. Imported tasks arrive paused. Secret properties go into files of `secrets/` and never into an output.
- Administration: the columns of the data tables can be resized with the mouse or the arrow keys. The browser keeps the widths per table, and Reset column widths forgets them.

- Administration: the scheduler runs five kinds of task. They rebuild Maven metadata, rescan a store with its catalog rows and counts, remove stale Docker upload sessions, back up `state.sqlite` and remove old work files of the write store. A task of another kind is listed and does not run.

- Logging: `serve` writes five files into a log directory: `server.log`, `requests.log`, `requests-classic.log`, `audit.log` and `tasks.log`. The directory is `logs/` in the data directory unless `serve --log-dir`, `PIPESMITH_REGISTRY_LOG_DIR` or `log_dir` in `config.json` names another. The value `off` turns the files off.
- Logging: a file rotates at 100 MiB and at the change of the day in UTC, and is compressed. Rotated files are kept 90 days after their day plus one day, at most 2 GiB per kind.
- Logging: `audit.log` holds one line per request that changes state, per sign in and sign out, per token issue and revoke, and per command that changes state. A line names the fields that changed and never their values. A command beside a running server hands its line to the server through `audit-pending/`.
- Logging: query values of `token`, `password`, `secret`, `key` and `access_token` are written as `***`. Each text field of a request line has a cap, and an outside value is escaped.
- Logging: `log-target add|list|test|remove` sends the JSON lines to syslog, GELF, Loki, OTLP, Splunk HEC, Elasticsearch or HTTP JSON. A running server reads the targets again every 5 seconds. A target secret is read with `--secret-stdin`, stored in `secrets/log-target-<name>` with mode 0600, and sent only over `https`, `tls` or to a loopback address.
- Logging: the log routes list the log files, return the end of a file or the whole file, and set logger levels.
- Logging: with the log files on, four load runs on the development machine served at least 7,590 requests per second (`docs/measurements/phase-7.md`).
- Figures: `catalog.sqlite` counts downloads per repository and day, and requests per day. `GET /api/metrics/requests`, `GET /api/metrics/downloads` and `GET /service/rest/v1/monthly-metrics` answer from these counts.
- Figures: every minute `serve` writes a sample of requests, bytes, CPU time and memory to `metrics.sqlite`. Overview draws them as four line charts for 24 hours, 7 days or 30 days. `PIPESMITH_REGISTRY_METRICS=off`, or the setting `metrics` of `state.sqlite`, turns the samples off. The file held 335,872 bytes with the most rows the rules keep (`TestMetricsFileSize`, 2026-11-20).
- Status: six routes of the status area answer. `GET /service/rest/v1/status/writable` answers `503` when the data directory takes no file.
- Secrets: the export tool of the source repository (`tools/h2export.sh`) takes `--with-secrets` and the set `secrets`. `import` of such an export takes over the npm and Docker API keys, the remote credentials and the LDAP bind passwords of the old product. An imported key signs its user in while the realm `NpmToken` or `DockerToken` is active. `token list` shows imported keys as `imported`, and `token forget-imported` removes them. A secret file that exists is kept, and the import names it.
- Writes: `repos write-settings <name>` shows and sets the write policy, `max_body_bytes`, `free_space_floor_bytes` and `write_store` of a hosted repository.
- Writes: a start with writes on scans the write store once and repairs a path with two live files.
- Writes: an npm document may hold at most 1,048,576 values, a jar directory is read up to 100,000 entries and 32 MiB, and a body has 4 hours in total.
- Accounts: `user add` and `user password` read the password from a file with `--password-file PATH` or from a pipe with `--password-stdin`. The file must be readable by its owner only (mode 0600 or 0400). `--password-stdin` is refused at a terminal. `user add` takes `--role` once per role, beside `--roles a,b`, and runs the same checks and stores the same password hash as `POST /service/rest/v1/security/users`. A running server takes the change within about a second.
- Security: a full table of 10,000 sign in pairs lets the idle pair with the oldest failure go. A client address, or an IPv6 /64, with 100 failures in 15 minutes gets no new pair. Sharp s and ss, and final sigma, count as one name.
- Security: a token of a directory user is bound to the entry it was issued for and is refused while the directory marks the entry locked or disabled.
- Security: `serve` warns at start when it binds a network address with `trusted_proxies` empty, and when group or others can read or write the TLS key file. `ldap` warns for every connection without TLS.
- Security: the source repository holds tests for command injection and for hostile archive entry names. Three parsers ran under fuzzing for 5 minutes each without a crash (`docs/measurements.md`, section Fuzz).
- Updates: the screen Updates, in the section Support beside Status, shows the install root, `update.json`, the trusted key with its fingerprint and the result of the owner and mode check, and the last switch. It reads `GET /api/updates` and never writes the key.
- Updates: `update` and `rollback` write one line per run to `releases/history.jsonl` and hold SIGINT, SIGHUP and SIGTERM until the switch or the way back ends. `update.json` takes `health_address` and `health_tls_cert`.
- Documentation: the manual has new chapters and sections for Proxies, Add Accounts and Signing Key, and flow figures for sign in, LDAP, npm, Docker, Maven, writes, scan, update, export, the way back and proxies. `docs/LOGGING.md` describes the log files, targets and figures.

## Changed

- The first command of 0.2.0 that opens `state.sqlite` migrates it to schema 5 (see Upgrade). `state show` no longer migrates: on an older schema it exits 1 and names the command that migrates.
- `catalog.sqlite` moves to version 4, with tables for proxies and for the daily counts. A binary that knows version 3 refuses a file of version 4.
- With writes off, `GET /service/rest/v1/read-only` answers `"frozen": false` while no freeze is set. 0.1.3 answered `true`.
- A password change with `user password` ends the Docker tokens and the sessions of that local user.
- A stored password form whose check costs more than 2,000,000 digests is refused. 0.1.3 took up to 10,000,000.
- Host names in the Bearer realm and in npm and REST addresses are lower case, with a port only when it is a valid number.
- `anonymous on --user <id>` refuses a user who signs in.
- A `memberOf` group outside `groupBaseDn` maps to no role while the base is set.
- `ldap ca` refuses a symbolic link and a file that others can write.
- `realms set` notes that the authorizing realm of the old product has no effect.
- A new `index.sqlite` is created with mode 0600. `serve` warns when others can read `state.sqlite`.
- The export bounds of 20,000 files and 2 GiB are settings: `export_max_files` and `export_max_bytes` in `config.json`, or `serve --export-max-files N` and `--export-max-bytes N`.
- An export of a folder leaves out the paths no archive may hold and exports the rest. The dry call names them in `left_out` and `left_out_paths` (at most 20). A folder that holds only such paths answers `409`.
- An OCI export also carries a Docker `manifest.json`.
- The systemd unit of the release names no `User=`, so systemd runs it as root as before.
- The release files are signed (see Verify). `update` checks the bundle with the key of `trusted_key`.

## Upgrade

- Verify the download and its signature, stop the service, replace the binary and start it again. In a container, run the image `0.2.0` on the same `/data` volume.
- 0.2.0 uses `config.json`, `repositories.json` and `index.sqlite` of 0.1.3 as they are.
- The first command of 0.2.0 that opens `state.sqlite` writes a copy of the file before it migrates it to schema 5. From 0.1.3 (schema 2) the copy is `state.sqlite.v2`. From 0.1.2 (schema 1) it is `state.sqlite.v1`. The copy has mode 0600 and stays until you move it away. It is the way back. `serve` and `user add` are such commands, and `state show` is not.
- A copy that exists with other content stops the migration. Move the copy away first.
- `update` refuses to run while a copy `<file>.v<n>` or `<file>.failed` is in the data directory. Move `state.sqlite.v1` of the 0.1.3 upgrade away before `update` installs 0.2.0.
- `catalog.sqlite` migrates to version 4. Its copy `catalog.sqlite.v<n>` is written only when the disk has twice the size of the file free. A data directory of 0.1.2 has no `catalog.sqlite`, and the first scan creates it with mode 0600.
- New files in the data directory: `logs/` with the five log files (folder 0750, files 0600), `metrics.sqlite` unless metrics are off, and `secrets/remote/`, `secrets/imported-keys` and `secrets/log-target-<name>` when you use those features. A second server on the same log directory writes no files and warns once.
- Writes stay off unless `serve --writes`, `PIPESMITH_REGISTRY_WRITES` or `"writes": true` turn them on. Requests to remotes stay off unless `serve --upstream`, `PIPESMITH_REGISTRY_UPSTREAM` or `"upstream": true` turn them on.
- Before the first `update` to a signed release, compare the fingerprint of `cosign.pub` with the one under Verify. Then install the key as the trusted key and name it in `"trusted_key"` of `update.json`, as the manual section Signing Key shows.
- `rollback` refuses to go back to 0.1.3, because `state.sqlite` then has a newer schema than that release knows. The way back to 0.1.3 is by hand:
  1. Stop the server of 0.2.0.
  2. Move `state.sqlite`, `state.sqlite-wal` and `state.sqlite-shm` out of the data directory.
  3. Rename `state.sqlite.v2` to `state.sqlite`.
  4. Move `catalog.sqlite` with its `-wal` and `-shm` files out of the data directory. The next `scan` of 0.1.3 writes it again.
  5. When you imported secrets, remove `secrets/imported-keys` and the files of `secrets/remote/` that the import wrote.
  6. Put the 0.1.3 binary back and start it.
- Users, roles, realms, tokens, LDAP connections, tasks and other changes made after the upgrade are lost on the way back, and so are the download counts.
- After an import with `--with-secrets`, delete the export folder. Two of its files hold passwords in clear text.

## Limits

- Proxies: a blocked remote, the fetch slots and the Docker tag lists live in memory and end with a restart. A Docker tag list keeps the first page of the remote. An npm proxy asks its remote for the full package document only.
- Proxies: routing rules come from the import, and the interface shows the routing rule screens as Not in preview. The proxy editor of the interface shows 60 as the timeout and describes `-1` in another way than the server reads it.
- Administration: a created blob store is a record with a path below `<data>/stores/`. Every hosted repository still writes to `stores/local-write`.
- Administration: a repository that only `repositories.json` defines, or that has content in a store of the old product, is saved and deleted on the host only. Server limits and Docker ports are set on the host only.
- Administration: a role in use is not deleted. An administrator cannot set the password of a directory user. A password must not be empty, and there is no minimum length.
- Administration: a user who holds the permission to check LDAP connections can make the server connect to any host and port.
- Administration: cleanup policies and their preview are not in this release.
- Administration: the freeze lives in memory and ends with a restart. A task without a known kind is listed as disabled with the reason.
- Logging: the level DEBUG has no effect yet. A task run that ends while `serve` stops loses its `end` line. A pending audit line can be taken twice after a crash. A command run by another system user than the server cannot hand its line to a running server.
- Logging: `loki` sends no `X-Scope-OrgID`, and `splunk-hec` sends no channel header. Only `otlp` bounds the size of a request body, at 64 MiB.
- Logging: with a log target that does not answer, a stop takes about 2 seconds, and the queued lines count as failed.
- Secrets: imported keys of the old product hold 32 random bits each, and no limiter counts wrong guesses of them. NuGet keys are imported, and no route reads them.
- Writes: on the development machine, 8 connections wrote files of 4 KiB at about 50 to 62 `PUT` per second. These are three runs on 2026-11-20 while other jobs loaded the machine (`docs/measurements/phase-4.md`, section Rate Drop). The cause of the drop from about 110 per second is known: disk syncs under the write lock of the index.
- Writes: a start with writes on scans the whole write store. Its time on a large store is not measured.
- Writes: replaced and deleted files stay on disk with a delete mark, so the write store only grows.
- Writes: an overwrite is not taken back when a later file of the same upload fails. The lock of `maven rebuild-metadata` holds inside one process only.
- Writes: there is no bound on parallel writes. A checksum `PUT` under 64 MiB hashes its artifact again on every call.
- Writes: a path that a store of the old product holds can be written again but never deleted (`409`). A checksum file that does not match its file is stored with a warning.
- Writes: Docker upload sessions live in memory, 256 per process and 64 per user, and end with a restart or after one hour without a request. A referrers request reads every manifest of the name.
- Writes: with writes off, `DELETE /service/rest/v1/components/{id}` answers `404`, also without credentials.
- Writes: a write adds no row to `catalog.sqlite` until the next scan.
- Security: behind a reverse proxy that is not in `trusted_proxies`, every client has the address of the proxy. Five wrong passwords for one name then block that name for everybody, and the session cookie gets no `Secure`. A NAT or CI address with 100 failures makes all its users wait up to 15 minutes for new pairs.
- Security: a kept successful check forgets no failure. A sign in of the interface and `npm login` get `429` at once while 5 checks of their pair run. A flood of unknown names takes the 16 places of an LDAP connection.
- Security: while any directory does not answer, npm and user tokens of directory users are refused. A name that two directories hold is refused for tokens. A removed directory user or a lost group still works for up to 300 seconds, and a session keeps its groups up to 12 hours. The binding of a token to its directory entry lives in memory, so after a restart a token binds at its first use.
- Security: npm and user tokens do not expire. A revoke does not end sessions or Docker tokens. Docker tokens are bound to no repository and cannot be listed or revoked.
- Security: stored HTML runs no script and sends no form, and still opens on the host of the registry. One certificate serves every listener, and a renewed certificate takes effect at the next start. `FORWARDED_ALLOW_IPS` trusts loopback by default.
- Security: the bind rule does not count anonymous access. While `state.sqlite` cannot be read, the last loaded state stays. Sessions live in memory. `state.sqlite.v1` keeps the unsalted SHA-1 and MD5 password forms of 0.1.2.
- Security: a search value of many wildcards costs about 1.1 seconds per 100 KB field.
- Updates: `update` and `rollback` need systemd and do not apply to a container. The update unit ran under systemd in an Ubuntu container only, and no update has run on a Linux host.
- Updates: `update --fetch` reads the generic package registry of a forge. The releases on GitHub are not in that form, so install 0.2.0 with `update <release directory>` after you download the release files.
- Updates: `rollback` restores no data file. The timer does not try again a version whose scheduled switch failed. `update` cannot install 0.1.2, whose `SHA256SUMS` lists three names twice.
- Browse: the viewer only reads, at most 2 MiB and 1,000,000 lines of a file, Wrap up to 5,000 lines and 1,000 find marks per row.
- Browse: a Docker repository exports one image per archive, named under `docker.io`. A Maven export in `~/.m2/repository` serves releases only. Windows device names such as `CON` and `NUL` still pass into an archive.
- Documentation: the OpenAPI document describes most answer bodies in words. The manual does not yet name `export_max_files`, `export_max_bytes`, `left_out` and `left_out_paths`.

## Verify

Compare the fingerprint of `cosign.pub` with this one before you trust the key:

```bash
openssl pkey -pubin -in cosign.pub -outform DER | sha256sum
```

The SHA-256 of the key of 0.2.0 is:

```text
2ca9a77b196bab0d81a95d464778f9989c08da84f6ca2d1327fd8987f47bb595
```

Then check the signature over `SHA256SUMS` and the files against it:

```bash
cosign verify-blob --key cosign.pub --bundle SHA256SUMS.sigstore.json --insecure-ignore-tlog SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
```

The bundle has no transparency log entry, so `cosign verify-blob` needs `--insecure-ignore-tlog`. The fingerprint above takes the place of the log.
