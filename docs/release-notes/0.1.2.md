# Pipesmith Registry 0.1.2

## Fixed

- `import` reads the LDAP row in the form the old product stores it. The host is an object of `hostName`, `port` and `protocol`, and six key names differ from the REST API, for example `systemUsername` for `authUsername`. The row has no group type: the import uses `dynamic` when `userMemberOfAttribute` is set and not blank, else `static`. Rows with the names of the REST API still import. 0.1.1 stopped with `host is not of type string`.
- `import` reads an empty `blobStoreQuotaConfig` as no soft quota. 0.1.1 stopped with `the soft quota of blob store "<name>" has no type or no integer limit`.
- `import` reads a Docker port stored with a zero fraction, such as `5000.0`. 0.1.1 dropped such a port without a message, so `serve` opened no Docker listener for the repository.
- A soft quota limit or an LDAP integer stored with a zero fraction imports as well. 0.1.1 stopped the import at such a value.
- `serve`, `config`, `repos`, `store list` and `docker-check` open an existing index without a write. While a `scan` in another process holds the index, they answer with the rows of the last finished scan. 0.1.1 waited 30 seconds and ended with `error: database is locked`.
- `GET /service/rest/v1/repositorySettings` and `GET /service/rest/v1/repositories/<format>/<type>/<name>` show a stored number with a zero fraction as an integer, `14511` for `14511.0`. 0.1.1 showed the stored form.
- After a sign in and after a reload, the interface marks each area whose read request `GET /api/areas` lists as refused, and it sends no probe. 0.1.1 drew the page only after every probe had answered, and the probe of the search screen was a search without a hit. Such a search reads every row of each repository the user may browse, so on a large index every sign in and every reload waited for it.
- On Linux, the password prompt of `serve --ask-ldap-password` drops every key typed before the prompt appeared. With 0.1.1 such keys could become part of the password.

## Added

- A migration runner opens `state.sqlite`. Its schema stays 1, so a file written by 0.1.1 needs no migration.

## Changed

- `import` stops at a Docker port that has a real fraction, lies outside 1 to 65535 or is no number, and names the repository. 0.1.1 dropped such a port without a message.
- `import` refuses an LDAP row that gives one field twice, in both forms or in both columns. When 0.1.1 could read such a row, it kept one of the two values.
- The read commands `config`, `repos`, `store list` and `docker-check` no longer increase the `generation` row of the `meta` table in `index.sqlite`.

## Upgrade

- Verify the download, stop the service, replace the binary and start it again. In a container, run the image `0.1.2` on the same `/data` volume.
- 0.1.2 uses the data directory of 0.1.1 as it is: `config.json`, `repositories.json`, `state.sqlite` and `index.sqlite`.
- Run `import` again on the same export before the start if the import of 0.1.1 stopped at an LDAP row or a blob store. Do the same if `config --docker-ports` does not list a Docker repository that has a port in the old product.
- The second import gives such a repository its Docker port, so `serve` opens a listener on it. If the old service on the same host still holds that port, `serve` stops with `cannot listen on <bind> port <port>: Address already in use`. Move the port before the start with `repos port <name> <port>`.
